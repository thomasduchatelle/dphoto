# 02.1 — Backend: tagging domain, persistence, GSI, and endpoints

Status: ready

## Description

Implement the catalog-side tagging capability end-to-end on the backend, following the data model in `specs/2026-11-media-tagging/design.md`.

- **Domain** (`pkg/catalog`): a Tag value object that parses and normalises a raw string (lowercase, no spaces, URL-safe; `namespace:value` split on the first colon; bare tag allowed for `favorite`). Operations to add a tag to a media and remove a tag from a media (owner-only). A query listing all medias carrying a given tag for an owner, across albums.
- **Persistence** (`pkg/catalogadapters/catalogdynamo`): store one item per (media, tag) as a sibling on the media partition — `PK={owner}#MEDIA#{id}`, `SK=TAG#{tag}` — mirroring the archive `LOCATION#` precedent (`pkg/archiveadapters/archivedynamo`). The item carries `MediaId` and `AlbumId` (owner + folder name). Medias returned for an album must include their tags (no extra query per media). Add a GSI partitioned by `{owner}#{tag}` to list medias by tag in `O(matches)`.
- **API** (`api/lambdas`, one folder per operation, see `list-medias/` for the pattern): implement the add-tag, remove-tag, and list-medias-by-tag endpoints exactly as pinned in `specs/2026-11-media-tagging/design.md` ("Client/server interface"), and add the `tags` field to the album medias response. (The list-owner-tags endpoint belongs to a separate story.)

Update `DATA_MODEL.md` with the new tag item and GSI.

The GSI must be declared in the CDK table construct `deployments/cdk/lib/catalog/catalog-store-construct.ts` (see `CatalogTableIndexes`). Note: until the `2026-09-retire-appdynamodb-schema` work lands, the schema is dual-maintained — also add the GSI to the legacy Go helper `pkg/awssupport/appdynamodb/create_update_table.go` so local/test bootstrap stays in sync, despite its eviction notice.

Load the `go`, `expose-rest-api`, and `cdk` skills.

## Dependencies

None.

## Acceptance criteria

- A raw tag string is normalised consistently; `favorite` round-trips as a bare tag.
- Adding then removing a tag leaves no residual item; adding the same tag twice is idempotent.
- Listing medias of an album returns each media with its tags, with no per-media query.
- Listing medias by tag returns every matching media (with its album) across albums via the GSI.
- The add-tag, remove-tag, and list-by-tag endpoints match the pinned contract (paths, verbs, `204`/`200`, DTO shapes); the album medias response includes `tags`; owner-only writes.
- `DATA_MODEL.md` updated; GSI present in both the CDK construct and the legacy Go helper.
- Tests follow the Go table-driven style.

## Out of scope

- Any web/UI work.
- CLI commands.
- Tag counts; visitor read access.
